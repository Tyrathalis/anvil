## Broke / surprised me

- **Forced-draw "winner" is garbage by construction**: `setGameOver(Draw)`
  runs `Player.onGameOver`, which marks EVERY surviving player as won;
  `GameOutcome.getWinningLobbyPlayer` then returns an arbitrary
  map-order pick — JVM-varying, so the smoke's determinism diff caught
  it (33/72 rows differed ONLY on `winner`, identical snapshots). Sched
  rows now extract a unique per-player winner (`nWon != 1 ⇒ -1`).
  Latent same wart in `CensusRun.certRow` and the seq-probe rows —
  harmless historically because the certify standard's unended-roll
  guard (payment_ceiling.py gates on `ended` for both pair rows)
  excluded exactly those rows from every M9 read.
- **rollSeed must key on the target turn, not the fork counter**: stage 2
  re-runs the positive SUBSET, so fp numbering shifts between stages and
  the fp-keyed derivation would have silently broken the spec's
  rollSeed-identity both-horizon trick. Caught in self-review before any
  data; keyed on (game seed, target turn, roll) now.
- Random-legal (local-oneshot) play realizes mostly mana abilities and
  lands; real multi-cast turns are ~1 per 4 games — the smoke mines 12
  games for 3 points. Fine for mechanics; the model-serve smoke rides
  the fresh census.
