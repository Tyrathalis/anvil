## Broke / surprised me

- A Charm root keeps the AI's last chosen mode attached as its sub-ability, so a `getSubAbility()` walk below a Charm sees a stale mode (Cryptic Command's Counter on an empty stack): nodes below a Charm are modes, never the spell's minimum.
- The validator's exit code mixes the mask's clause with the pre-existing host-not-among check; the paired gate now reads the mask's summary line.

- A modal spell's targets live in its modes (`additionalAbilityLists["Choices"]`), invisible to a `getSubAbility()` walk — and the label records the chosen mode's targets on the root plan, so the decoder's label space includes them.
- The heuristic targets a spell on the stack as the CARD in the stack zone (what `getAllCandidates` returns), not as the stack entry; and its Explore / divided-damage logics bypass `canTarget` (shroud, hexproof) — the label is not a definition of legal.
- Kozilek's Command costs {X}{C}{C}: a test board without colorless sources made the scan look wrong when it was right.

- `ls | head` truncated the main checkout's `data/pool` listing, so the worktree got half the links and the harness's `--pool` mode refused to start; link the whole directory's entries, not a hand list.
- The check-in's relay reached this session directly for the first time (both FAILED events) — the bracketed-ref matching works from a bridge worktree.

- A single-module `mvn -pl forge-ai compile` cannot resolve the reactor's `${revision}` poms offline; `-am` is required even for a compile.
- The fork's `TargetRestrictions` has no `setValidTgts`; the X-dependence test uses real cards (Agadeem's Awakening vs Blazing Shoal) instead of a synthetic node.
- The surface decoder's player key was keyed by registered seat against self-first player rows since Build 3 (surfaces.py `opt_pi`): a representation swap from seat 1, not a decode bug. Fixed here; the warm start adapts.
- `getAllCandidates` returns the CARDS of spells on the stack when the zone list includes Stack, and never the abilities; the union emits stack entries as `stk` refs only (the realizer resolves `onStack` refs by host id).
