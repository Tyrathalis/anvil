## Broke / surprised me

- **The self-match class got a third scalp:** the read-chain waiter
  captured the i015 read's PID via `pgrep -f "final_read.py …"` — which
  matched the waiter's OWN quoted command line — so it waited on itself
  forever while both reads finished and notified hours earlier. The
  standing watcher correctly flagged the phantom STALL. Lesson now
  absolute: PID acquisition must be self-reported (`$!` at spawn or the
  process writing its own pidfile), never pattern-derived. The drill
  evals ran with `$!` capture and behaved perfectly.

  one quarantined frame — the fix class working as a statistic.
