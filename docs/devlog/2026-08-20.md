# Session 2 — the salvage review (diagnosis → fix → re-smoke, ADR-0066)

## Done

- **Salvage RESOLVED without needing the census repro** — the smoke
  data alone localized it. Per-(job,arm) × roll outcomes were
  DETERMINISTIC (job 7 arm 3 salvaged 8/8 rolls, arm 4 ok 8/8) ⇒ a
  plan property, not executor flakiness; failing arms clustered on
  dual/multi-ability boards; `spare:Badlands x2` appearing TWICE as
  separate goals (two classes, same two physical cards) was the bug
  visible in the wire labels. Root cause: **the DFS tracked
  availability per class (`remaining[]`); feasibility is per host
  card** — both of a dual's ability-classes pick the lowest-id copy
  first, so two-color plans committed the same card to two shards.
- Minimal repro `testDualLandNotDoubleCommitted` (2× Hallowed
  Fountain vs {W}{U}) failed pre-fix with exactly the predicted
  duplicate-host message; passes post-fix. Fix = `usedHosts` set in
  `DfsState` (within-class pick = lowest-id atom with uncommitted
  host). Fork `37bde8051e`, payment suite 15/15.
- **Reason-coded salvage born** (the diagnosis channel the smoke
  lacked): `executeDirected(p, pc, why)` → `PayDirective.execWhy` →
  certify row `exec_why` (`canplay:`/`costs:` + host#id@atomIdx);
  `payment_certify.py read` now prints the salvage gate + failure
