- **Combat ordering never fires**: the engine runs the modern no-assignment-order rule
  (`GameRules.orderCombatants` defaults off; `Combat.orderBlockersForDamageAssignment` short-circuits),
  so "ordering" is trigger order + move-to-zone order. The trigger windows are real decisions
  (Solitude's ETB vs its evoke sacrifice, n = 2); most move-to-zone windows are graveyard orderings
  where the order is irrelevant, the library ones (Brainstorm-style put-backs) the few that matter.
- **Damage has zero sub rows by construction, not by bug**: a search window is a quiescent
  MAIN1/MAIN2 window and a copy stops at the seat's next quiescent window — on the pass path the
  start of combat — so no copy crosses blocks and damage; the leaf value has never seen a damage
  assignment. The mainline carries ~350 multi-blocker windows per 1,000 games (imitation labels).
- **The enumerator's damage family assumed the legacy order** (lethal in list order, the remainder
  on one blocker); under the rule in force any split is legal and the AI orders internally.
- Evening-2 lesson check: neither ordering callback bundles a joint decision (trigger targets are
  chosen as each trigger hits the stack, after the ordering; the damage map is the whole decision
  and the engine validates the sum) → no gate. Distillation has nothing to teach here (ordering's
  single-roll leaf σ 0.065, the largest kind, against a headroom at noise) → imitation only.
