## Broke / surprised me

- The mint-cost question dissolved into `ls -la`: the banked sweep's
  lane timestamps WERE the bench (anchor timelines on artifacts). No
  code was run to answer fork 3's gating question.
- The replay-parity rabbit hole went three levels deep before
  bottoming out: (1) probe stores are model-generated ⇒ lanes need the
  generating ckpt served; (2) generation SAMPLED ⇒ serve must sample,
  and determinism holds only because noise is seeded per
  (game_seed, dec_s); (3) a sampled server REFUSES wire-only fork
  completions ⇒ `--fork-instrument` (built for M7 forced-branch
  instruments) is exactly the needed mode. Each level was already
  solved by existing machinery — the session's work was recognizing
  that, plus the witness tool so the next replay never re-argues it.
- The generation flag set differs from the census sweep's
  (`-paytelemetry` off, `-reask` on) — cloning the sweep's lane
  template verbatim would have silently broken parity. run.json as
  the single source of replay truth is the standing rule's core.
- **The parity verb's first verdict was a false FAIL with a real
  finding inside**: every replay diverged only at its last 2 decisions
  — the jar EARLY-STOPS the mainline after the game's final fork turn
  (2× autoPassCancel, forced end; also why the banked sweep was fast).
  The prefix through the fork turn is byte-identical. The criterion is
  now "exact prefix through the last fork turn, trailing autoPassCancel
  excluded, winners not compared".
- **The mint launch failed once for real and once in my head.** Real:
  12 simultaneous Forge JVM boots died silently mid-FModel-init (exit
  0, zero rows — the old DONE-on-exit-0 gate marked them done; the
  CHRONICLE_BINDER trace in their logs is CAUGHT per-entry boot noise,
  a red herring). Fix: ~10 s/lane boot stagger + DONE gated on ≥90%
  expected row count + per-lane logs + a 30-min stall watcher.
  Imagined: my `pgrep -c "jav[a] -Xms3g"` liveness check matches COMM
  (15 chars), so a pattern with args returns 0 forever — combined with
  Forge's multi-minute quiet deck-load phase I read a healthy staggered
  fleet as dead. Memory updated (pgrep -f rule #4). Latent bug fixed in
  passing: `-range` takes (start, COUNT), not (start, end) — harmless
  for the start-0 init stores, wrong for any i001+ store.
