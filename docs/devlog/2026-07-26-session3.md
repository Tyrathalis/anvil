## Broke / surprised me

- **L1+L2 shipped a visibly broken window, and only running it showed that.**
  `SpriteBatch` and `ShapeRenderer` each build an ortho projection from
  `Gdx.graphics` **in their constructor** and never revisit it, and
  `Graphics.begin()` only sets logical bounds — it never touches the projection
  or calls `glViewport`. So with the "complete" T1 applied, a window dragged to
  1720×1382 kept drawing the UI at 1280×720 **anchored to the GL origin in the
  bottom-left**, rest of the window black. The fix is small (`Graphics.resize()`
  re-orthoing both, plus `animationBatch`); finding it was not. Corroboration
  that this was always the unfinished shape: **`FrameRate.resize(int,int)`
  already existed and was called from nowhere.**
  - The generalizable lesson, which applies directly to item 5: *this class of
    UI change is cheap to write and is not verifiable by reading.* Item 5 step 1
    has a pixel-identity gate that only means something if it is actually run.

- **`xdotool` cannot inject pointer input on this Wayland session.**
  `xdotool mousemove` leaves `getmouselocation` at `0,0` — XTEST pointer warping
  is refused by the compositor. `xdotool windowsize` works, because that is a
  window-management request rather than input injection. Net effect: the resize
  work was automatically verifiable and the deck-chooser work was not.

- **A near-miss worth writing down.** Almost referenced `forge.util.Utils`
  constants from `GameLauncher` for the size floor. `Utils` computes its statics
  from `Gdx.graphics` at class-init, so touching it from the launcher would
  initialize it before the graphics context exists. Used literals with a comment
  saying why.

- `pkill -f "…jar-with-dependencies"` killed its own shell (the pattern
  self-matched, same family as the known `pgrep -f` note). Bracket a character.
