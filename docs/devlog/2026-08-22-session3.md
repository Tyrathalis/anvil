# 2026-08-22 (session 3)

Chronicle session. The track had been dormant three weeks — last Chronicle
commit was `fedfea5126` (2026-08-01/02) while M8/M9 ate the hours — and the
user came back from real phone use with feedback. That feedback is D5.

## Done

- **Read the state of the track.** Chronicle sat at D3 v1 built / D4 build-path
  solved / D5 never started. Two records were stale: D4's done-when
  ("the daily loop runs on the phone") has actually been met for a while and
  was never written up, and D5 had no opening entry despite the user
  dogfooding it. Both fixed.
- **Diagnosed both reveal-scene complaints in the source before touching
  anything.** Both were real defects, not taste:
  - *"Moving my finger partway and then back finishes opening the pack."*
    `pan()` did `tearProgress += Math.abs(deltaX) / ...`. The absolute value
    means the return stroke accumulates exactly like the pull. There was also
    no `panStop`/release handler at all, so partial progress never decayed —
    it just sat there until the next touch pushed it over. And
    `TEAR_DRAGS_TO_OPEN` was **1.1 screen widths**, which no single swipe can
    physically cover, so `fling()` (which fired on any direction, including
    vertical) was the only way most opens actually happened.
  - *"The top section tilts instead of stretching or tearing."* Literally
    that: the strip above the tear line was one rigid quad with
    `dx = tearProgress * artW * 0.35f` and `angle = tearProgress * 7`. A slide
    and a 7° rotation. No tear in the tear animation.
- **Rebuilt both** (`2177e66f6d` on `playable`):
  - Gesture: direction commits on first horizontal travel and only travel that
    way counts; pulling back closes proportionally; `panStop` springs it shut
    on a short release; `fling` completes only along the committed
    axis+direction and above a velocity floor. Progress is measured from an
    anchor against absolute `x` rather than accumulated deltas, so
    lift-and-resume is correct. One committed swipe over half the screen width
    opens a pack (`TEAR_SWIPE_FRACTION`).
  - Animation: 16 vertical columns, each whole until the tear reaches it, then
    split at its own point on a stable per-pack zigzag (`jag(i)`, hashed from
    `packIndex` so a pack always tears the same way). Columns peel with a lag
    from the gripped end, so the split **propagates** across the wrapper as you
    pull instead of the whole top lifting at once; each peeled column slides,
    rises and curls by its own progress. The fresh edge draws as one connected
    zigzag, bright where the paper just gave way. The peel follows the
    direction actually torn (`tearFlyDir`).
  - Nine new constants joined the pacing block — the tuning surface is intact.
- **Took the design finding as an ADR** —
  [ADR-0070](../decisions/ADR-0070-chronicle-effort-reward-sink.md). The user's
  third complaint ("nothing to do with the cards but look at them"), refined
  mid-session into the requirement that matters: *something that works as a
  time sink, so if you feel like putting more time into the experience you get
  rewarded for it.* That reframing is better than "add deckbuilding" — it names
  the property, and deckbuilding is one instantiation of it. Pinned as **pin 8,
  above the MVP/stage line**, and it outlives D6: if the purse doesn't satisfy
  it, the pin stands and the next candidate is scoped against it.
- **Promoted the kitchen-table stretch to deliverable D6** and deferred the D5
  numbers pass behind it. Updated the plan, the sketch's MVP slice spec, the
  Status bullet, and the project map (Now panel, track card, ADR index, footer).

## Broke / surprised me

- **The MVP's known hole arrived exactly on schedule and nobody noticed for
  three weeks.** MVP slice spec v0 cut battler/tournaments/market and made
  kitchen table the stretch — "build only if the slice lands early." The slice
  landed on time, the stretch was never built, and the shipped loop is
  *all grants*: ration and stipend on a timer, and a buylist that pays out less
  than packs cost by construction. Every channel is a grant; none of them scale
  with effort. The design predicted this and the dogfood measured it, but the
  gap between "documented as a stretch" and "measured as the thing that ends
  the habit" is three weeks of nobody looking.
- **`TEAR_DRAGS_TO_OPEN = 1.1f` should have been caught at build time.** The
  constant is a fraction of screen width. 1.1 of them is not reachable by a
  finger. Every successful open in D3 testing went through `fling()`, which
  masked it completely — the feature "worked" for the whole of D3's live round.
- **A false green from my own shell.** `mvn ... | tail -10 && echo "COMPILE OK"`
  printed COMPILE OK off `tail`'s exit code while Maven had actually failed for
  a missing `-am`. Grep for `BUILD SUCCESS` in the maven output, never `&&` off
  the tail of a pipeline.
- Compiling `forge-gui-mobile` alone fails offline: the sibling
  `forge-*` 2.0.15-SNAPSHOT jars aren't in `~/.m2`, so it needs `-am` to build
  them from the reactor.

## Next session picks up

  ADR-0070 before any code:
  1. *The purse's flavor.* Cash for a kitchen-table game is the easy build and
     the weakest fiction. Ante is period-authentic, in the era's actual rules,

     owned copies, and how duplicates across printings count.
