# 2026-08-22 (session 3)

Chronicle session. The track had been dormant three weeks — last Chronicle
commit was `fedfea5126` (2026-08-01/02) while M8/M9 ate the hours — and the
user came back from real phone use with feedback. That feedback is D5.

## Done

- **Read the state of the track.** Chronicle sat at D3 v1 built / D4 build-path
  solved / D5 never started. Two records were stale: D4's done-when
  ("the daily loop runs on the phone") has actually been met for a while and
  was never written up, and D5 had no opening entry despite the user
  dogfooding it. Both fixed.
- **Diagnosed both reveal-scene complaints in the source before touching
  anything.** Both were real defects, not taste:
  - *"Moving my finger partway and then back finishes opening the pack."*
    `pan()` did `tearProgress += Math.abs(deltaX) / ...`. The absolute value
    means the return stroke accumulates exactly like the pull. There was also
    no `panStop`/release handler at all, so partial progress never decayed —
    it just sat there until the next touch pushed it over. And
    `TEAR_DRAGS_TO_OPEN` was **1.1 screen widths**, which no single swipe can
    physically cover, so `fling()` (which fired on any direction, including
    vertical) was the only way most opens actually happened.
  - *"The top section tilts instead of stretching or tearing."* Literally
    that: the strip above the tear line was one rigid quad with
    `dx = tearProgress * artW * 0.35f` and `angle = tearProgress * 7`. A slide
    and a 7° rotation. No tear in the tear animation.
- **Rebuilt both** (`2177e66f6d` on `playable`):
  - Gesture: direction commits on first horizontal travel and only travel that
    way counts; pulling back closes proportionally; `panStop` springs it shut
    on a short release; `fling` completes only along the committed
    axis+direction and above a velocity floor. Progress is measured from an
    anchor against absolute `x` rather than accumulated deltas, so
    lift-and-resume is correct. One committed swipe over half the screen width
    opens a pack (`TEAR_SWIPE_FRACTION`).
  - Animation: 16 vertical columns, each whole until the tear reaches it, then
    split at its own point on a stable per-pack zigzag (`jag(i)`, hashed from
    `packIndex` so a pack always tears the same way). Columns peel with a lag
    from the gripped end, so the split **propagates** across the wrapper as you
    pull instead of the whole top lifting at once; each peeled column slides,
    rises and curls by its own progress. The fresh edge draws as one connected
    zigzag, bright where the paper just gave way. The peel follows the
    direction actually torn (`tearFlyDir`).
  - Nine new constants joined the pacing block — the tuning surface is intact.
- **Took the design finding as an ADR** —
  [ADR-0070](../decisions/ADR-0070-chronicle-effort-reward-sink.md). The user's
  third complaint ("nothing to do with the cards but look at them"), refined
  mid-session into the requirement that matters: *something that works as a
  time sink, so if you feel like putting more time into the experience you get
  rewarded for it.* That reframing is better than "add deckbuilding" — it names
  the property, and deckbuilding is one instantiation of it. Pinned as **pin 8,
  above the MVP/stage line**, and it outlives D6: if the purse doesn't satisfy
  it, the pin stands and the next candidate is scoped against it.
- **Promoted the kitchen-table stretch to deliverable D6** and deferred the D5
  numbers pass behind it. Updated the plan, the sketch's MVP slice spec, the
  Status bullet, and the project map (Now panel, track card, ADR index, footer).

## Broke / surprised me

- **The MVP's known hole arrived exactly on schedule and nobody noticed for
  three weeks.** MVP slice spec v0 cut battler/tournaments/market and made
  kitchen table the stretch — "build only if the slice lands early." The slice
  landed on time, the stretch was never built, and the shipped loop is
  *all grants*: ration and stipend on a timer, and a buylist that pays out less
  than packs cost by construction. Every channel is a grant; none of them scale
  with effort. The design predicted this and the dogfood measured it, but the
  gap between "documented as a stretch" and "measured as the thing that ends
  the habit" is three weeks of nobody looking.
- **`TEAR_DRAGS_TO_OPEN = 1.1f` should have been caught at build time.** The
  constant is a fraction of screen width. 1.1 of them is not reachable by a
  finger. Every successful open in D3 testing went through `fling()`, which
  masked it completely — the feature "worked" for the whole of D3's live round.
- **A false green from my own shell.** `mvn ... | tail -10 && echo "COMPILE OK"`
  printed COMPILE OK off `tail`'s exit code while Maven had actually failed for
  a missing `-am`. Grep for `BUILD SUCCESS` in the maven output, never `&&` off
  the tail of a pipeline.
- Compiling `forge-gui-mobile` alone fails offline: the sibling
  `forge-*` 2.0.15-SNAPSHOT jars aren't in `~/.m2`, so it needs `-am` to build
  them from the reactor.

- **Ran the D6 design round same session** —
  [ADR-0071](../decisions/ADR-0071-d6-design-round.md). All three ADR-0070
  questions settled plus the two the build forced. Headlines: cash purse by
  default with **ante as an opt-in stake** at a better payout; opponent = a
  small cast of **named rival collectors** whose seeded pools grow along the
  player's own timeline; **reference-only** deck legality; `DeckGeneratorBase`
  over a `DeckGenPool`, behind a pool-in/deck-out seam Anvil can take over.
- **Fork archaeology says D6 needs no new machinery.** `DeckGeneratorBase`
  takes an arbitrary `PaperCard` pool and Chronicle's collection already is
  one; `FDeckEditor.DeckEditorConfig` exposes exactly `getCardPool()` and
  `usePlayerInventory()`; `MatchController.hostMatch()` + `startMatch(...)`
  with `adventure.scene.DuelScene` as the harvest template — the same Adventure
  harvest pattern Chronicle already used for `ShopData` and `SaveFileData`.

## Broke / surprised me (round 2)

- **The ante question has a better answer than "harsh vs. classic."** Ante
  doesn't just raise stakes — it *inverts the loop*. Every reward channel in
  Chronicle is accumulation (binder filling, NEW badges, first-pull glints,
  completion bars), so an ante loss doesn't merely fail to reward, it undoes
  earlier sessions. Seed integrity makes that permanent and unrerollable by
  construction. That reframing is what turned it from a taste call into cash
  by default + ante as an opt-in risk axis.
- **`usePlayerInventory()` already means exactly the chosen legality.** I went
  looking for how much work reference-only-with-per-deck-caps would be and it
  turned out to be Quest's existing semantics, sitting on a hook the editor
  config already exposes. The chosen option was the free one.
- **There are no period decklists to import, and that's the historically
  correct answer.** 1993–94 predates published deck tech; the earliest
  documented lists (Dolan '94 Worlds, Weissman's "The Deck") land after the MVP
  window closes at FEM. All three shipped Forge corpora are anachronistic for
  the window — the LDA archetype models cover Modern/Legacy/Historic/Pauper and
  Legacy's archetypes are Sneak Show and Merfolk; the 505 quest precons are
  modern WotC precons; the 786 `geneticaidecks` are GA-evolved Legacy. This
  made the design *easier*: the period-correct opponent is another kitchen-table
  player with a jank collection, which is precisely what pool-restricted
  generation produces, weaknesses included.
- **The `>23h` Android update caveat in my notes was stale.** The strictly-newer
  gate shipped in `73d9c55025` — `AssetsDownloader.java:120` is
  `snapsTimestamp.after(buildTimeStamp)`. A published build is offered to the
  phone immediately.

- **Built D6 the same session** — headless (`c647ba081e`) then screens
  (`92708b5452`). Shared-file footprint **zero**; Chronicle suite 57 green;
  full desktop suite 506 run / 0 failures / 11 skipped.

## Broke / surprised me (round 3 — the build)

- **The rival pool wanted to be keyed on pack index, not day.** First cut seeded
  a rival's packs by (run seed, rival, day), which reshuffles their whole
  collection every morning — technically deterministic, but it makes a
  "collector" whose binder is different every day. Keying on (run seed, rival,
  **pack index**) and letting the day pick only *how many* packs of that fixed
  sequence they own makes the collection strictly cumulative for free, and each
  pack's computable acquisition day gives the era bound. The difficulty model
  fell out of that with no difficulty knob anywhere.
- **`DeckGenPool` is count-blind.** It's `Map<String, PaperCard>` keyed by NAME,
  so a pool containing exactly one Black Lotus will happily yield four. Anything
  building decks from a real collection has to clamp afterwards. Test written
  first for this one and it earns its keep.
- **A pack-only rival owns literally zero lands.** Forge's era sheets put no
  basics in 1993-94 boosters (the documented D2 deviation), so basics can't come
  from the collection — they're supplied outside it and forced to a period
  edition. Correct anyway, since basics were free at the kitchen table.
- **Determinism was free.** Every forge-core deck generator routes randomness
  through `MyRandom`, exactly like `BoosterGenerator` — so the same
  `MyRandom.setRandom(new Random(seed))` trick `ChroniclePackGenerator` already
  uses makes deck building reproducible. Nothing to build.
- **Match launch needed no shared-file change, though Adventure's precedent says
  otherwise.** Adventure reports its results through an `isMobileAdventureMode`
  branch inside `MatchController.finishGame()` — a second mode-specific branch
  there is exactly what Chronicle's isolation convention exists to prevent.
  `HostedMatch.setEndGameHook` plus `getGame().getOutcome().isWinner(...)` does
  the job from outside. Entanglement budget held at zero.
- **Ante had to be forced OFF explicitly.** `GameRules` inherits the global
  `UI_ANTE` preference. If the player has ante on for normal Forge play,
  Chronicle would have staked their collection without asking — in a mode whose
  entire loop is accumulation, and where seed integrity makes the loss
  permanent. ADR-0071 makes ante opt-in and that opt-in isn't built yet, so the
  table pins it off.
- **Decks must not touch Forge's shared deck store.** The playable build shares
  it with the research harness, whose `launch --pool` gates on installed-deck
  content hashes — a Chronicle deck landing there would silently move a number
  in an unrelated project. A small `IDeckController` routes the stock editor's
  saves into the run instead.
