### Archaeology first (4 parallel scouts over the fork)

- **Seed integrity works today**: every RNG site on the 1993–94 booster path
  routes through `MyRandom`, which the determinism-hooks rebase made
  thread-local + settable — `MyRandom.setRandom(new Random(contentsSeed))`
  with save/restore around `BoosterGenerator.getBoosterPack(template)` gives
  committed pack contents. Reseed per pack (the foil rejection loop burns a
  variable draw count even for `Foil=NotSupported` sets). One landmine noted
  for post-MVP eras: `BoosterSlot.replaceSlot()` uses raw `Math.random()` —
  unreachable before ~2018 sets, must be fixed upstream before the window
  crosses that line (comment pinned in `ChroniclePackGenerator`).
- **`SaveFileData` is libGDX-bound** (module cycle + Pixmap/Vector2 overloads)
  ⇒ headless port `ChronicleSaveData` in forge-gui, keeping the
  `DecompressibleInputStream` migration substrate and the IOException-sentinel
  protocol, dropping the toolkit overloads. Versioning: Quest's explicit
  version-int ladder (Adventure has NO version number — its shims are
  unbounded) + Adventure's containsKey defensiveness. GZIP container,
  header-first for the slot browser.
- **No FModel entanglement**: Quest's `FModel.getQuest()` has 238 call sites —
  the anti-pattern. Chronicle follows Adventure's own-singleton shape;
  shared-file hooks so far = **3 additive lines in `ForgeConstants`**, zero
  elsewhere (dir creation via the QuestDataIO static-init idiom, so no
  PROFILE_DIRS edit either).
- **Test infra**: desktop tree only; `AITest` base gives the one-time card-DB
  load (~3.4 s shared per JVM); tests see the real `forge-gui/res/`; save IO
  is File-pathable so tests use temp dirs, never the real profile.
- **Edition data confirmed**: all 9 window sets carry era-authentic `Booster=`
  lines (8-card ARN/ATQ/DRK/FEM, `UncommonRare` combined sheets, † and
  a/b/c/d art variants); starters exist for the four core sets only
  (historically correct); ATQ prints the same name at split rarities
  (Urza's Mine 83a/b U vs 83c/d C) ⇒ notables priced by NAME, never
  name+rarity; collation identity stays at the PaperCard key.

- `ChronicleCollection` — printing×finish inventory on forge-core `CardPool`,

### Found en route (the suite caught a real design hole)

The tick guard was first written as effective-day *inequality*; the
grace-window test tripped it and exposed the exploit: **winding the device
clock backwards a day would re-arm the tick**. Fixed to a strictly monotonic
comparison — clock rollback can never re-arm; the grace window still covers
the honest midnight opener. The seed-integrity pin protected pulls from
savescumming, but the tick needed its own monotonicity to resist clock
scumming — recorded as an addendum on the plan's pin 5.
