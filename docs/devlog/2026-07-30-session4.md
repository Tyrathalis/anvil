## Broke / surprised me

- **v7 was dead on arrival in the field.** The first real update attempt (the
  user's own install) aborted with `HTTP 400 for .../res/adventure/Realm of
  Legends/decks/legends/nicol_bolas.dck` — the delta URL builder concatenated
  paths into URLs without percent-encoding, and the res tree carries 30K+
  paths with spaces (plus `#` `'` brackets `&` `!` unicode and a literal `%`).
  Every v1–v6 delta happened to touch only URL-safe paths; the v7 delta (months
  of upstream res churn) was the first big enough to hit the class. Exactly the
  v4 `..`-substring incident's sibling: a property the artifact always had,
  unexercised until a real plan touched it. My post-publish routine verified
  manifest *parsing* through the shipped jar but not URL *construction* — the
  gap is now closed (the routine fetches the production-built URL for a
  space path live and hash-matches it).
- Nothing was half-applied anywhere: downloads abort before any apply, so all
  clients sat safely on ≤07.29 with a "failed to download" dialog.
- **v8 published same evening (fork `09974ab3ea`) with the fix and a fully
  automatic migration:** (1) segment-wise `DeltaUpdater.encodePath` — pinned
  by a new HTTP end-to-end test with hostile filenames, validated failing
  first on the exact field path (a real HttpServer rejects raw spaces like
  GitHub; the existing file:// e2e was too lenient to ever catch this);
  (2) bridge manifest — a fix to the updater cannot ship through the updater
  it fixes, so plain entries list ONLY the jar (release asset, URL-safe — the
  one plan ≤07.29 parsers can always complete) and the full 54,727-entry list
  rides on `#2 ` lines legacy parsers skip as unknown future headers;
  (3) res self-heal — after the jar-only hop the local build EQUALS the
  published one, so the strictly-newer gate would never re-open and res would
  silently stay stale under the new jar; on equal builds with no sync stamp, a
  size-only diff (no speculative 2GB hash pass; same-size content changes
  self-correct at the next release's hash-verified delta) offers to complete
  the update, stamp written after any successful apply. DeltaUpdateTest
  10/10 (3 new). Pre-publish gate extended: the bridge manifest parsed with
  the user's actual shipped 07.29 jar (1 entry, jar only) AND the v8 jar
  (54,727 entries); the encoded URL for the failing path fetched live and
  hash-matched. Post-publish routine re-run in full on the published assets.
