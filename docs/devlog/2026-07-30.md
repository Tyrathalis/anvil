## Broke / surprised me

- **The pre-push guard fired on a wholly public branch, and was wrong.** It
  tests whether the pushed *tree contains* a marker file, not whether the diff
  introduces one — so once #11457 rebased onto a master that now contains
  `LogSafe.java`, an entirely public branch tripped a security guard. Narrowed
  the marker list on evidence (`git cat-file -e upstream/master:<path>` per
  marker, not assumption) and re-exercised all four directions before trusting
  it. **Standing lesson, twin of the stacking one: a guard keyed on file
  presence decays into a false positive the moment that file goes public, and a
  guard that cries wolf teaches you to reach for its override.** Re-check the
  marker list whenever anything merges.
- **The old unlock plan had gone stale without anyone noticing.** Written 07-27,
  it said "when reports 2 and 4 land, lift everything as one batch." The
  condition was met today — but the plan assumed all four reports would end
  *fixed*, and two did not. Running it as written would have published two live
  findings framed as vulnerabilities. A pre-registered plan is still a plan
  written under old information; check its premises when it fires, not just its
  trigger.
- Advisory-fork API mechanics, refined by doing: force-pushing the head branch
  **updates an open PR in place** (no close/reopen, no browser), and GraphQL
  `updatePullRequest` works — but `addComment` returns `FORBIDDEN — this action
  is forbidden on workspace repositories`, and REST issue endpoints 404
  throughout. Content and metadata are pushable; conversation is browser-only.
  The maintainer's messages arrive in the *advisory* thread anyway, which has no
  API at all.
- Nothing else: no engine surprises, and the research path was untouched
  throughout. The pinned research fork has zero delta from any of this.
