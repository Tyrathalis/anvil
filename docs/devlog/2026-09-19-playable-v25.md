## Broke / surprised me

- The both-sides conflict resolution left the tap-angle method unclosed in
  `CSubmenuPreferences`: the two added methods shared the closing brace
  that sat outside the hunk. The mobile-dev jar build never compiles
  `forge-gui-desktop`, so the jar built clean and checkstyle in the test
  run was the first thing to notice. Rule for the next sync: after a
  mechanical resolution, compile every module a resolved file lives in
  before trusting the jar.
- Surefire cannot order classes (`-Dtest` order is not honoured,
  `-Dsurefire.suiteXmlFiles` breaks the reactor at forge-core, a standalone
  `-pl forge-gui-desktop` cannot resolve siblings because their installed
  poms carry `${revision}`). Running `org.testng.TestNG` directly on the
  reactor classpath from `dependency:build-classpath` is the recipe.
- The `sleep N; …` wait pattern is blocked in this harness; a detached
  launch plus an `until [ -f done ]` wait is the shape that works.
