## Live test round (same session, author playing the mobile-dev jar)

The author played the scene immediately; six fixes + two dev tools landed
across five pushed commits (`4542ff9b30` → `ba94fc4cfd`):

- **Dev-mode testing actions** (`4542ff9b30`): "New day" + "+$20" buttons on
  the Chronicle home screen, visible only with Forge's dev mode on. Day
  advance = `ChronicleTimeline.devRewindOneDay()` — rewinds the
  last-collected marker so the tick re-arms, leaving the clock-scum guard
  untouched; day contents are deterministic per day index, so seed
  integrity holds by construction (unit test pins all three properties;
  suite 35 green). Chosen over multiple-saves (backlog: slot browser) and
  plain cash-only: day advance compresses exactly what dogfood needs
  (rations, paydays, stock rerolls, releases).
- **Booster art never downloaded — anywhere** (`10bae5b6fd`): two stacked
  causes. `ImageCache.imageKeyFileExists()` falls through to `return true`
  for every product prefix, so `CachedCardImage.fetch()` never fires for
  `b:` keys (the D2 binder tiles were silently placeholders all along);
  and bare `b:CODE` keys can't match the fetcher's saved filename (it
  stores the list's full `LEA.jpg`-style name). `ChronicleHub
  .boosterArtKey()` resolves codes through `booster-images.txt` to a
  fetchable full-filename key and kicks the download directly.
  **`imageKeyFileExists` fallthrough = upstream fix candidate.**
- **Reveal NEW badge glinted re-pulls** (`10bae5b6fd`): the acquisition log
  shipped mid-run, so log-blind early openings made every re-pull look
  first. First-pull now also requires the collection to hold no copies
  beyond this batch's (count cross-check); sold-and-repulled stays
  non-new via the log side. Binder NEW was always separate and correct.
- **Pacing + legibility** (`10bae5b6fd`): cascade 0.13/0.09/0.05 →
  0.18/0.12/0.18 flip/fly/dwell; soft holds for every non-jackpot first
  pull (0.45s commons, 0.75s uncommons); the invisible auto-pause hint
  replaced by a pulsing "Tap to continue" pill; revealed-row long-press
  now zooms the pressed mini (draw-geometry-mirrored hit test), not the
  latest.
- **EDT crash on bulk open** (`ab17ab900d`): `ImageFetcher.fetchImage`
  asserts the EDT; the art-key kick and the preload batch ran on the
  loading-overlay thread. Both hop to the EDT now; the background thread
  keeps only file polling. (The crashed attempt had already committed its
  packs — openSealed runs before the reveal — so those cards reached the
  binder without a ceremony.)
- **Starter deck-box art** (`7f96dd11ac` + `570954bc8d`): generalized
  ImageFetcher's booster branch into `fetchProductImage()` and routed the
  `o:` prefix through it (**upstream candidate** — zero behavior change
  for `b:`), then discovered the only host in
  `tournamentpack-images.txt` — `downloads.cardforge.org` — **has no DNS
  record anymore** and forge-extras mirrors only boosters/pets. So
  `RevealPack` carries a fallback art key: starters draw booster art
  today and self-upgrade to the real product shot if upstream ever
  rehosts. Every stock list still pointing at cardforge.org is dead
  weight — worth an upstream report.
- **The CI "Test build failed" mail = FCollectionTest.testCompletableFuture
  flake, now fixed** (`ba94fc4cfd`): the test predates upstream
  `b858b48fde` ("remove Collections.synchronized") and kept asserting
  that unsynchronized concurrent removes land exactly — they race on the
  backing ArrayList and intermittently lose one. Stress harness
  (3000 iterations): stock body failed at run 30 with the exact CI
  signature; externally-synchronized variant 3000/3000 clean. Fix =
  synchronize the test's mutation; the property it still pins
  (snapshot iteration during mutation never throws) is real and passes.
  **Upstream candidate**, with a caveat recorded: any live game code
  doing unsynchronized concurrent FCollection removes has the same race.
